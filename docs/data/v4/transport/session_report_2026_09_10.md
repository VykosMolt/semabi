## Implemented product path

- Added a local authenticated HTTP service, durable connection/job/execution storage, persisted versioned operation artifacts, OpenAPI 3.1 description, and a standalone example client. It runs with the existing Python/Playwright stack and no runtime model or paid API.
- Integrated connection, bounded learning, progress inspection, operation discovery, invocation, and execution inspection. Several connections can remain open with separate browsers/contexts. Fixed a Playwright lifetime defect so reconnecting or closing one does not invalidate another.
- Learned creation through two varied UI trials, then extended the same mechanism to exact local reads and updates. Operations contain their arguments, resolution procedure, prerequisites, effect checks, support/evidence, source version, and limited scope. They do not require global entity identity.
- Added fresh-state argument resolution, local record ownership, independent text and link-destination channels, closed-disclosure filtering, field-local Clear control handling, and URL-argument proposals from visible labels when HTML typing is absent.
- Added direct and advertised-menu editor discovery, unique unnamed-field support, single-value replacement, and a narrowly disclosed numeric-context-label prior supported by two contrasting read trials.
- Added retained editor/field/control checks, changing-default and sibling-draft guards, stale-contract withdrawal, per-call limits, attempted-action accounting, uncertain-write preservation, and service idempotency/conflict handling. Interrupted writes are not replayed; target-application exactly-once delivery is not claimed.
- Added a matched cached-form/read/update replay baseline that consumes the same learned artifacts and argument objects. Shared acquisition and assistance are charged to both arms. It is a conditional replay baseline, not an independently learning browser agent.

The [developer quickstart](../../../product_quickstart.md) contains runnable setup, discovery, invocation and inspection commands. Core implementation is in `semabi/service.py`, `semabi/compiler/runtime.py`, `semabi/compiler/browser_session.py`, `semabi/compiler/surface.py`, `semabi/compiler/artifacts.py`, `semabi/baselines/cached_form.py`, and `examples/client.py`.

## Remaining product limitations

The supported path is local, exact-value and conservative. There is no general natural-language planner, arbitrary multi-step task compiler, pagination/search strategy, broad widget support, MFA/SSO support, global object identity, learned endpoint relation, aggregation or JOIN guarantee. Other populated editors, ambiguous values, changed contracts, remounted elements and missing effect witnesses can stop execution. Successful visible checks do not certify hidden state or absence of every possible side effect. No universal-support, competitive-superiority or YC-readiness claim is supported by this session.
