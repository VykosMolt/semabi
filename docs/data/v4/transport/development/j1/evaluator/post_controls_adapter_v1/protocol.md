## Exact loader seam

Temporarily wrap only the loaded controls instance's `module` function. Always
delegate to its captured original loader first. Only the invocation with exact
name `_j1_post_controls_evaluation` and canonical `Path` value `J1 / evaluate.py`
receives a correction; every other invocation returns the original result
unchanged. Reject an evaluator instance reused by the original loader.

For each fresh evaluator, capture its original `verify_preservation` and reader.
Install a verifier wrapper that calls the original first, then the accepted
hash-only helper over the full new and held commitment set, and returns the
original manifest unchanged. Enter the accepted sidecar context manager on that
fresh evaluator. It retains both full original F/P gates and changes only the
two admitted actor-accounting path leaves in returned copies, under its already
accepted checks. Retain both contexts in one `ExitStack` until the original
controls `main` finishes or fails.

The original controls body calls `authenticate` twice, loading a fresh evaluator
each time. Both receive the same accepted correction and original-first guard.
Keep all original `authenticate`, `verify_package`, `verify_dependencies`,
`audit_run`, `assess`, `main`, and output bodies unchanged. The second original
authentication, package check and dependency check remain before the original
final write. No output writer is replaced. Restore both readers and verifiers,
the controls loader and `sys.argv` on success and failure, with restoration
results recorded in the audit.

## Output and failure retention

The result must be a new canonical absolute identity inside the original
`post_controls_v1` directory because its unchanged authentication requires that
location. The separate audit directory must be new and inside this launcher
directory. Both identities are frozen by the new source manifest and must be
disjoint from all held source/input/artifact identities and first-pass roots.
The audit directory reserves the single attempt before any execution imports;
the original result writer and separate audit writer both create exclusively.
An existing attempt is rejected and never overwritten or retried.

Original stdout is captured, retained verbatim in the audit and replayed once
without a launcher summary. Original result bytes and return codes zero/two
remain unchanged. Later original custody failures remain invalid results. An
exception, commitment drift or restoration failure produces a failed launcher
audit, retaining any existing partial result by hash. Recheck all commitments
after restoration and before audit completion. Failures before an authenticated
output identity cause no output mutation; their launcher error must be retained
by the caller. No actual controls execution is authorized until root accepts
the held source and focused proof.

## Focused proof boundary

The focused checks use invented metadata and declared evaluator/data stubs to
exercise only the new seam: exact loader selection, both fresh authentications,
original-first guard failures, later original failures, exclusive outputs,
stdout/error retention and restoration. They do not rerun the original 113
package checks or accepted 42+2 sidecar checks, and do not replace the accepted
complete seven-charge reconciliation evidence. Every stub and source import is
reported in the focused result. No fit, forecast, browser, fixture call, action
or actual diagnostic run is part of preparation; no universal syscall monitor
is claimed.
