## Production mechanism and coverage

The production diff has exactly the two intended changes. After all ordinary and
promotion search decisions, `compile_v4` adopts both `result.hypotheses` and that
hypothesis object's `G`. Search `_build` constructs the abstractor with `Hx.G`.
The selected hypothesis and abstractor therefore read the same observation
store. The fix does not assign a shared graph into copied hypotheses after types
or caches have been derived. Pinned and legacy-identity construction already
obtain a coherent `(H, G)` from `build_hypotheses` and retain their existing paths.
The search function signature and all V2 production code remain unchanged.

This repairs the demonstrated split: `A.ensure` inserts the unseen signature
into `A.G`, and `H.parse_units` now reads that same graph. Freezing the abstractor
also freezes the graph actually read by its hypotheses. Existing graph code
continues to add per-observation structure while skipping learned template/text
statistics, and existing emission/control freezing is unchanged. No identity,
field, normalization, acquisition, objective or comparison policy is modified.

The added tests are meaningful integration regressions in the existing frozen-
transform test home. They exercise real inferred compilation, `consequence.fit`
with no supplied reading, pinned and legacy branches, and candidate construction
with independent copied source/sibling graphs. Unseen pages change values, names,
a header and status text; parsing, control recognition and abstraction all run.
The checks retain learned vocabulary/header/template keys, abstract types,
emission values and resolved controls, and confirm the selected model's training
observations have unchanged abstractions/control families after unseen reads.
The ordering check compares two independently fitted frozen models. Source and
sibling observations/vocabulary remain unchanged and their learning flags stay
true when the candidate is frozen.

Promotion coverage is natural: a two-transition synthetic log produces an
accepted `text[_]` promotion through the actual search objective, and the test
asserts both the promotion and a `promote_leaf` move before reading a novel page.
No forced winner or patched search result substitutes for that branch. These
finite integration checks establish the targeted ownership and freezing

## Development instruments and resolved findings

The initial corpus adapter accepted an arbitrary snapshot file set and depended
on an implicit corpus-root environment variable. The initial comparison script
could label an unchanged T1 score as G1 and copied all-click summaries without
reconciling their raw rows. Those were concrete provenance/denominator findings;
root preserved the unexecuted proposals under `instrument_revisions/` and revised
the tools before G1 measurements.

The current `run_corpus.py` requires the exact G1 freeze path and schema and
reuses the scorer's canonical learner-path allowlist. It verifies the unchanged
corpus instrument, `link_probe.py` dependency and adapter itself against the
freeze. It binds the persistent reconstructed root, checks its manifest digest,
verifies every canonical file and rejects unexpected files before importing the
legacy corpus instrument. The corpus environment is set explicitly before import.
Only the output location and location of authenticated input bytes change; the
original `settled_reading`, split 0.999 fit, target selection, RULE/decision-list
scoring and visible-binding measurement remain intact.

The output must resolve inside the G1 development directory and must not already
exist. Original baseline paths cannot be selected. A copied freeze and
`adapter.json` distinguish the actual command, owner, input root and hashes from
the original instrument's inherited nominal command/owner labels. The outer
`run_job.py` supplies the actual process lifecycle. Existing partial outputs are
preserved instead of overwritten or silently resumed.

The temporary reconstruction was unavailable after resumption. `rebuild_inputs.py`
redirects the original reconstruction instrument's output and copies its three
source manifests into the new output area, protecting the old validation file.
Independent byte checks now confirm all 45 persistent files: all 36 consumed
inputs match the original baseline validation exactly, and the other nine are
merge-provenance JSONs. The original 80-file baseline manifest remains intact.
The corpus input manifest and its reconstruction/helper provenance are retained;
no authentication or cache regeneration was used.

`freeze_development.py` openly declares disclosed G1 development and records old
and new hashes for exactly the two changed runtime files. The original T1 freeze,
initial histories and candidate bytes remain bound. Sealed evaluator bytes are
hashed only by the evaluator-owned freeze builder; scoring/corpus children
verify the allowed runtime section and do not open those sealed files. Tests,
controls, measurement helpers, reconstruction and analysis metadata are recorded
separately as verification inputs. The output freeze is created exclusively.
This is a new runtime phase, not an updated claim about original T1 performance.

`summarize_development.py` requires the source HEAD, complete runtime-file digest
and freeze path/hash/count/status to match each score's own phase manifest. It
compares identical training/evaluation/candidate evidence and all eight reading
IDs. All query and emission step sequences must equal the complete charged-click
sequence; coordinates and results join to that raw ledger, and stored all-click
summaries are recomputed and compared. Task summaries retain the fixed 10/8
targets. The two initial and four distinct terminal histories are compared once,
with no invented new acquisition contrast. Saved model equality, owner presence,
runtime failures and identity surfaces remain separate measurements. The tool
makes no automatic H1/H2/H3 success claim.

Bounded read-only executable checks during this review accepted all ten original
T1 source/freeze records and recomputed all 240 model/channel summaries. A T1
score was rejected when checked against the changed G1 runtime hashes. Corpus
invocations targeting the original baseline output or original T1 freeze were
rejected before measurement; no output directories were created. These checks
fit no model and do not replace review of actual later G1 results.
