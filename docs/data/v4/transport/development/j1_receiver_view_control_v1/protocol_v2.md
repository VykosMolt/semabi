## Status and error semantics

The execution receipt uses `semabi.j1.receiver_view_execution.v2`. Other raw
artifact names and the held control's result schema are unchanged inside a new
exclusive output directory. Fit counts and stage flags are retained separately
from the result status. `FIT_INCOMPLETE` is no longer an execution status.

| Status | Meaning |
| --- | --- |
| SETUP_LIMIT | An explicit driver or held-control admission check rejected setup before intervention, or the unchanged control returned SETUP_LIMIT without making its arms. No A/B conclusion follows. |
| CONTROL_INCOMPLETE | Any unexpected exception at any stage, interruption, exception after the control call begins, partial-output write failure, failed postflight, final-receipt write failure, or incomplete result returned by the held control. |
| CONTROL_CAPTURED | The held control completed its capture/equivalence checks, postflight passed and no driver error remains. This is not a scientific success verdict. |

Explicit admission failures are instances of the driver's `SetupLimit` or the
authenticated held control's `SetupLimit`. An unexpected `TypeError`, `OSError`,
JSON decoding failure or native fit exception cannot become a representation
finding merely because it happened before the control. A failed final receipt
write updates the printed terminal status to `CONTROL_INCOMPLETE`; partial files
remain for preservation. Exit code zero requires `CONTROL_CAPTURED`, verified
postflight and no driver findings. Every other completed status returns two.
An external kill may prevent final capture; retain its actual process outcome.
