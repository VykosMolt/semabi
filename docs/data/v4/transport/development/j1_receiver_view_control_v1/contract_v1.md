## Question and fixed intervention

Does exposing an already represented checked radio owner through the existing
view-selection query boundary supply information that the unchanged abstraction
omits? The unit of this control is a disclosed observation and its admitted
native pre-state. It is not a fresh-interface, blinded, held-out, JOIN, or
production-transport test.

Both arms retain the same actual native operator, receiver-typed parameter,
action owner, object instances, object identities, attributes and references.
They use shallow state/ParsedObs copies so derived collection-position caches
cannot leak from one arm into the other. Only B's copied `view` may carry an
additional value: the key of the uniquely checked radio's already admitted
owner, under that radio's **existing parsed family key**. No owner, entity,
type, reference, attribute, key alias, or operator parameter is invented.

For the retained cohort the existing family key is `radio:Select receiver`.
The instrument must recover and check this key through every radio's
`node_key` and instance slot; a fresh unmatched string is forbidden. Derive
the B value from raw role/label/checked, tree membership and the admitted
parsed-owner mapping, without consulting the expected binding, operator
positives, emitted arguments, later observations, oracle data or hidden IDs.
The generic control label itself does not name an owner.

## Calls and equivalence

Use unchanged native `referring._selection_queries(op, var, evidence)` in
each arm. Evidence is four `(state, {var: checked_owner})` pairs derived from
the input observation and admitted native ownership. This is explicit
identity-assisted diagnostic binding, outside the operator's original
positive-transition set. It must not be presented as normal induction.

Initialize both copied ParsedObs caches identically. Run the actual
`_member_positioned` guard on the exact existing family key and all view
candidate keys in both copies; never prefill an invented False. Record
guard results and require equal cache contents before measuring the arms.
The query function retains its own guard calls. A veto is a competing
structural-policy result, not a reason to rename the slot or bypass policy.

Record every candidate returned by each arm. For the union of returned
candidates, call the unchanged native selection `Query.denotation` on all
five states in each arm, retaining zero, singleton and plural denotations.
Keep candidate origin (A/B), exact query form, owner/object IDs, guard results
and the complete added-view-field record. Do not reduce the report to the
first candidate chosen by a higher-level search.

Before and after each arm, verify the complete state/operator projections
and original objects remain unchanged, allowing only B's declared view
field. The copied parser metadata and initialized guard cache must agree.
Preserve missing/ambiguous owner, unknown raw boolean, duplicate selection,
unusable key, absent parameter, occupied original view key, guard veto and
equivalence failures explicitly. No injection is allowed on inadmissible
ownership; no checked radio leaves B without the added value.

## Assessment after raw preservation

The held callable is `control_v1.run_control`, with keyword-only arguments
`fit`, `referring`, `copier`, `setup_receipt` and `training_bytes`. It performs
no file I/O. `training_bytes` contains the exact two named JSONL files above.
The receipt must carry `status=ROOT_ADMITTED`, the intended `source_head`,
`source_freeze_sha256`, `fit_provenance_sha256`,
`runtime_origin_receipt_sha256`, `operator_record_sha256` and the five
`raw_to_normalized_associations`. The driver must authenticate those bindings;
the callable checks their syntax and relevant native/input correspondences,
not the truth of a caller's attestation. The operator digest uses the supplied
Copier's transition registration, which the future driver must make explicit.

The result includes complete typed snapshot dependencies, raw candidate and
denotation rows, copied-state projections, local object identity audit tokens,
guard results and setup/copy/mutation findings. `CONTROL_CAPTURED` means those
calls completed with the checked equivalence; it is not a scientific success
verdict. `SETUP_LIMIT` permits no intervention. `CONTROL_INCOMPLETE` preserves
any partial calls or copy/guard activity. There is no command or native driver
in this draft, and neither the callable nor a new fit has been executed.

Support for the bounded omission requires valid and equivalent setup, no
native query in A that tracks all four observed selections, and B's existing
radio-family query naming the visibly selected admitted owner on each
checked page while naming none on the unchecked page. A later assessment
must independently check the raw-to-native correspondence; agreement with
the same input-derived binding used for query search is not independent
proof of owner correctness.

A guard veto supports a structural-policy explanation. Missing ownership,
identity, type or parameter supports a representation/setup limitation.
Wrong/plural B denotations with valid setup falsify sufficiency of this
particular view intervention. An A query that already follows the selection
contradicts the proposed omission at this setup. Equivalence or custody
failure makes the control inconclusive; preserve it without a success claim.

None of these outcomes establishes persistent radio state, patch identity,
both endpoint references, learned existential witnesses, JOIN competence or
production transport. Root owns execution, preservation and assessment.
