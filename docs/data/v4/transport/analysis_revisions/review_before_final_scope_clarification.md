The unchanged search code deepcopies hypotheses and their graph, then constructs
an abstractor using the separately passed graph. Compilation likewise adopts
`result.hypotheses` but retains the earlier `G`. `A.ensure` inserts new
observations into `A.G`, while `H.parse_units` reads `H.G`. The preserved missing
signature tracebacks and pre-run real-pipeline reproducer agree with this code
mechanism. The proposed `G = H.G` after final selection and
`V4Abstractor(Hx.G, Hx)` in search repair that ownership invariant without oracle
identity input or rebinding already-derived candidate state to a shared graph.

This is acceptance of the bounded repair rationale, not of unexecuted code.
Its stated checks for unseen-observation parsing/control recognition/abstraction,
frozen statistics, and source/sibling graph isolation remain necessary, including
the relevant ordinary, promoted, pinned and legacy-identity paths. Runtime
availability alone cannot pass H1 or H2. Normalization, editable-field binding,
clock policy and possible suffix-statistics issues remain separate development
questions until causally tested.

T1's complete negative evidence, controls, exposure and failure analysis are
sufficiently preserved, reproducible and reviewed to close this phase now.
Preserve this analysis checkpoint, then begin G1 using these disclosed histories
as development data. Reserved transport needs its own later freeze. There is no
need to clean away negative residuals or rerun the frozen first pass to permit
that transition.
